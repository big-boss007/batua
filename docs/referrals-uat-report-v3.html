T6 – Referral Codes Table Display BUG

Steps:

  1. Navigate to /admin/referrals with an active program and existing referral codes.
  2. Observe the "All Referral Codes" table.

Expected: Table shows Code, Mobile (formatted phone number), Type (Standard/Creator pill), Conversions count, Status (Active/Inactive pill).

Actual: Table renders, but the "Mobile" column shows a raw UUID (customer_id) instead of a phone number.

Root Cause: formatMobile(code.customer_id) at line 292 of +page.svelte receives the UUID of the customer, not a phone number. The ReferralCode type only contains customer_id (UUID), and no customer name/phone lookup is performed. The formatMobile function tries to format any string as a phone number, producing garbled output for UUIDs.

Severity: MEDIUM — data display is incorrect, but does not block core functionality.

Suggested Fix: Either (a) join customer phone in the backend list_merchant_referral_codes query, or (b) batch-fetch customer details on the frontend and display name/phone.

API:

GET /referrals/merchant/{merchant_id}/codes?page=1&limit=50 → 200 (array of ReferralCode)
T7 – Analytics Metrics Cards BUG

Steps:

  1. Navigate to /admin/referrals with an active program.
  2. Observe the 4 metric cards: Total Codes, Referrals, Conversions, Conversion Rate.

Expected: Metrics show correct totals. Conversion Rate displayed as percentage (e.g. "50.0%").

Actual: Total Codes, Referrals, and Conversions counts are correct. Conversion Rate displays incorrectly — shows "0.5%" instead of "50.0%" when the backend returns conversion_rate: 0.5 (a fraction, not a percentage).

Root Cause: Backend get_referral_analytics computes conversion_rate = total_conversions / total_referrals as a 0–1 fraction. Frontend line 275 displays {analytics.conversion_rate.toFixed(1)}% without multiplying by 100.

Severity: LOW — cosmetic/display issue; raw data is correct.

Suggested Fix: Either multiply by 100 on the frontend ((analytics.conversion_rate * 100).toFixed(1)%) or return the value as a percentage from the backend.

API:

GET /referrals/analytics/{merchant_id} → 200 { total_codes, total_referrals, total_conversions, total_suspicious, conversion_rate }

Backend API — Referral Conversion & Anti-Fraud

These test cases cover backend-only logic verified through code review and API contract analysis.

API-1 – Referral Conversion: Happy Path PASS

Endpoint: POST /referrals/convert

Logic verified (code review):

  • Validates referral code exists and is active
  • Validates code belongs to the correct merchant
  • Validates program is active
  • Checks max referrals per customer limit (if configured)
  • Runs fraud checks before rewarding
  • Creates wallets for referrer/referee if they don't exist (get_or_create_wallet)
  • Creates idempotent ledger entries for both referrer and referee with BucketType::ReferralReward
  • Creates conversion record with fraud signals
  • Increments referral code stats (total_referrals, total_conversions)
POST /referrals/convert { merchant_id, referral_code: "RIYA10", referee_id, order_id? } → 200 { conversion_id, referrer_rewarded: true, referee_rewarded: true, fraud_signals: [] }
API-2 – Anti-Fraud: 5 Detection Signals PASS

Fraud signals verified (code review of helpers::check_fraud):

  • self_referral — referral_code.customer_id == referee_id
  • duplicate_ip — same IP used on this code before
  • duplicate_device_fingerprint — same device fingerprint used on this code before
  • high_velocity — 10+ conversions for this code in the last hour
  • new_account_referee — referee account created within last 5 minutes

Behavior: If any signal is detected, is_suspicious = true. Suspicious conversions are recorded but neither referrer nor referee is rewarded. Conversion stats increment total_referrals but NOT total_conversions.

API-3 – Code Generation: Vanity & Random PASS

Logic verified (code review of helpers::generate_referral_code):

  • Vanity code (explicit): If req.code is provided, uppercased and used directly. E.g., "riya10" → "RIYA10"
  • Vanity code (auto): If is_vanity = true but no code given, customer name is used. First 2–4 alpha chars uppercased + 2 random digits. E.g., "Riya Sharma" → "RIYAS42"
  • Random code: 8-character alphanumeric (A-Z, 0-9) generated from UUID bytes
  • Duplicate handling: Unique constraint on referral_codes.code returns 409 Conflict
POST /referrals/codes { merchant_id, customer_id, code: null, is_vanity: true, is_creator: false } → 201
