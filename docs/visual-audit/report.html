2. Dark Theme - Component-Level Failures

The theme toggle works correctly (3-state: light / system / dark). Dark mode applies globally via CSS variables. However, several components use hardcoded light-theme colors that don't adapt.

Dark mode works globally, but specific components have hardcoded light backgrounds

High

The ThemeSwitcher cycles through light → system → dark. The global CSS variables (--color-background, --color-surface, --color-text) correctly switch via the [data-theme='dark'] selector. Most pages render well in dark mode. However, several components use hardcoded hex colors that create jarring light islands on a dark background.

Overview: Dark mode works correctly - all CSS variable-based elements adapt
Gift Cards: Dark mode works well - stat cards and table adapt properly

Pages with dark mode failures (hardcoded colors):

Wallet Policies: Green "PREVIEW" card uses hardcoded #f0fdf4 gradient - doesn't adapt
Campaigns: Earning formula card and campaign cards have light backgrounds
VIP Tiers: Tier badges (Bronze/Silver/Gold/Platinum) have white pill backgrounds; tier program info section has a light border that doesn't adapt well
Referrals: Mostly adapts well, but the status bar and config preview have subtle hardcoded tints
The Campaigns page has the worst dark mode rendering: the entire earning formula card and all campaign template cards appear as bright white rectangles on a dark background. This is the highest-impact fix.
Suggested Fix: See Section 8 below for the full list of hardcoded hex values that need to be replaced with CSS variable equivalents. Priority: Campaigns earning formula > Wallet Policies preview > VIP Tiers badges > Referrals status bar.

3. Stat Card Styling Inconsistency

Four pages use stat/metric cards with two different implementations and inconsistent sizing.

Two different stat card implementations with different padding, font sizes, and structure

High

The Overview page uses a dedicated MetricCard component with larger padding and font sizes. All other pages (Gift Cards, Referrals, Influencers) use custom inline .stat-card divs with smaller sizes. This creates a visible inconsistency.

Overview: MetricCard component - 3 per row, larger font (2xl), padding space-6
Gift Cards: Custom .stat-card divs - 5 per row, smaller font (lg), padding space-4/5
Referrals: 4 stat cards per row, yet another subtle sizing variant
Influencers: 2 stat cards, same custom style as Gift Cards
Property Overview (MetricCard) Gift Cards / Referrals / Influencers
Component MetricCard.svelte Inline .stat-card divs
Padding var(--space-6) (24px) var(--space-4) var(--space-5) (16px 20px)
Value font-size var(--font-size-2xl) var(--font-size-lg)
Label font-size var(--font-size-sm) var(--font-size-xs)
Icon support Yes No
Sub-text (e.g. currency) Yes No
Additionally, the Overview's "Active Jewels" value is styled green, "COD Pending" is orange, while "Active Customers" and "Redemptions" are black. On Gift Cards/Referrals/Influencers, all stat values are black. There's no system for when stat values should be colored.
Suggested Fix: Standardise on the MetricCard component for all stat card use cases. Add size variants (size="compact" for pages with 4-5 cards) that reduce padding/font proportionally. Move all custom .stat-card divs to use MetricCard.
Affected Files
  • frontend/src/lib/client/modules/admin/ui/MetricCard.svelte (extend with size prop)
  • frontend/src/routes/admin/gift-cards/+page.svelte (migrate to MetricCard)
  • frontend/src/routes/admin/referrals/+page.svelte (migrate to MetricCard)
  • frontend/src/routes/admin/influencers/+page.svelte (migrate to MetricCard)

4. Page Header Pattern Violations

Pages should follow a consistent pattern: h1 title + subtitle + optional action button (top-right).

Campaigns page is missing its h1 heading entirely

High

The Campaigns page starts directly with a description paragraph (<p class="page-desc">) and the earning formula card. There is no <h1> heading, making it the only admin page without a title.

Campaigns page: No h1 "Campaigns" heading - jumps straight to description text

Three pages missing subtitle descriptions

5. Status Indicator Inconsistency

Status is displayed as Pill component on some pages, custom colored spans on others.

Mix of Pill component and custom styled spans for "Active/Inactive" status

High

Some pages use the Pill component from the library (correct approach), while others use custom <span class="status-active"> elements. This creates visual differences in border-radius, padding, background opacity, and font weight.

Page Implementation CSS Classes
Gift Cards Pill component (correct) .pill-gc-success, .pill-gc-info, etc.
Transactions Pill component (correct) .pill-success, .pill-error, etc.
Influencers Pill component (correct) .pill-success, .pill-neutral
Settings (Connectors) Pill component (correct) .pill-success, .pill-neutral
Earn Rules Custom span (inconsistent) .status-active, .status-inactive
Notifications Custom span (inconsistent) .template-item-status with inline styles
Referrals (program status) Colored text + dot (inconsistent) .status-dot + .status-text
Additionally, the Pill class naming is fragmented: .pill-gc-* on Gift Cards, .pill-success on Transactions, .pill-log-* on Notifications logs. These should use a unified naming scheme.
Suggested Fix: Migrate all status indicators to use the Pill component with the global variant classes defined in app.css: .pill-success, .pill-error, .pill-warning, .pill-info, .pill-neutral. Remove all custom .status-* spans and page-specific .pill-gc-* / .pill-log-* classes.
Affected Files
  • frontend/src/routes/admin/rules/+page.svelte (replace .status-active spans with Pill)
  • frontend/src/routes/admin/notifications/+page.svelte (replace custom status spans with Pill)
  • frontend/src/routes/admin/referrals/+page.svelte (replace .status-dot with Pill)
  • frontend/src/routes/admin/gift-cards/+page.svelte (rename .pill-gc-* to .pill-success etc.)

Gift Cards "active" status pill is lowercase while all others are title-case

Low

On the Gift Cards table, the status pill reads "active" (lowercase). On all other pages it displays as "Active" (title-case). This is a minor but noticeable text inconsistency.

Suggested Fix: Capitalise the status value before rendering: use text-transform: capitalize on the pill, or transform the value in the template.

7. Table Implementation Inconsistency

Some pages use the Table component from the library, others use custom HTML tables or div-based layouts.

Three pages use custom HTML tables instead of the Table component

Medium

The component library provides a Table component (used by Transactions, Customers, Gift Cards, Settings/Connectors). However, Referrals, Influencers, and Earn Rules use either custom <table> HTML or div-based row layouts. This leads to different hover states, row heights, header styles, and overall visual feel.

Page Implementation Row Hover Header Style
Transactions Table component (correct) surface-2 hover Uppercase, muted
Customers Table component (correct) surface-2 hover Uppercase, muted
Gift Cards Table component (correct) surface-2 hover Uppercase, muted
Settings/Connectors Table component (correct) surface-2 hover Uppercase, muted
Referrals Custom <table> (inconsistent) Different hover Uppercase, but different padding
Influencers Custom <table> (inconsistent) Different hover Uppercase, but different padding
Earn Rules Div-based rows (inconsistent) Card-like hover No column headers
Suggested Fix: Migrate Referrals and Influencers to use the Table component with cell snippets (same pattern as Transactions). The Earn Rules page uses a card-row layout which may be intentional for richer content, but should at minimum share the same border/shadow/hover CSS variables as the Table component.
Affected Files
  • frontend/src/routes/admin/referrals/+page.svelte
  • frontend/src/routes/admin/influencers/+page.svelte
  • frontend/src/routes/admin/rules/+page.svelte

8. Hardcoded Colors (Dark Theme Failures)

Several components use hardcoded hex colors that will not adapt when dark mode is eventually fixed.

Wallet Policies: Points preview section uses hardcoded green hex colors

Critical

The "Points Preview" card on the Wallet Policies page has a green gradient background, green text, and green borders - all using hardcoded hex values. When dark mode is fixed, this section will remain a bright green card on a dark background.

The "PREVIEW" card (top right) uses hardcoded #f0fdf4, #dcfce7, #16a34a, #14532d, #059669
CSS Property Current (Hardcoded) Should Be
Background gradient #f0fdf4, #dcfce7 color-mix(in srgb, var(--color-success) 8%, var(--color-surface))
Border #bbf7d0 color-mix(in srgb, var(--color-success) 30%, var(--color-border))
Label text #16a34a var(--color-success)
Value text #14532d var(--color-text)
Suggested Fix: Replace all hardcoded hex values in the .points-preview section with CSS variable-based equivalents using color-mix() for tinted backgrounds.
Affected Files
  • frontend/src/routes/admin/wallet-policies/+page.svelte (lines ~293-342)

Campaigns page: Earning formula and campaign cards are entirely light-background in dark mode

Critical

The Campaigns page is the most visually broken page in dark mode. The "Active Campaign Earning Formula" card, active/upcoming campaign cards, and all festive template cards render with bright white/light backgrounds against the dark page background.

Campaigns in dark mode: Earning formula card and all campaign cards are bright white islands
Suggested Fix: Replace hardcoded backgrounds in the campaign cards and earning formula section with var(--color-surface) and var(--color-border). The green/blue top borders on campaign cards can remain as accent colours.
Affected Files
  • frontend/src/routes/admin/campaigns/+page.svelte (earning formula card, campaign cards, template cards)

VIP Tiers: Tier badges have hardcoded white backgrounds

Medium

The tier badge pills (Bronze 1x, Silver 1.5x, Gold 2x, Platinum 3x) use hardcoded white/light background colours. In dark mode, they appear as bright white pills inside dark cards.

VIP Tiers in dark mode: Tier badges are bright white pills on dark background
Suggested Fix: Replace hardcoded badge background colours with color-mix(in srgb, var(--tier-color) 15%, var(--color-surface)) to create a tinted version that adapts to both themes.
Affected Files
  • frontend/src/routes/admin/loyalty/+page.svelte (tier badge styles)

Referrals page: Banner, config preview, and status bar use hardcoded colors

High

Multiple sections on the Referrals page use hardcoded colors:

  • .reconfigure-banner: hardcoded #fffbeb background, #fde68a border, #92400e text
  • .config-preview: hardcoded blue gradient
  • .status-bar: hardcoded green/red status colors
Suggested Fix: Replace with CSS variable equivalents: var(--color-warning) for banner, var(--color-primary) for config preview, var(--color-success)/var(--color-error) for status.
Affected Files
  • frontend/src/routes/admin/referrals/+page.svelte (lines ~398, ~419, ~428-433, ~475-478)

9. Subtitle CSS Class Fragmentation

Pages that do have subtitles use three different CSS class names for the same visual element.

Three different CSS class names for the same subtitle pattern

Low
CSS Class Used By Font Size
.subtitle Overview, Gift Cards, Referrals, Influencers var(--font-size-sm)
.page-subtitle Transactions, Customers var(--font-size-base)
.page-description Earn Rules var(--font-size-sm)

Note that .page-subtitle uses font-size-base while the other two use font-size-sm, creating a visible text size difference between Transactions/Customers and other pages.

Suggested Fix: Consolidate to a single class name (e.g., .page-subtitle) in all pages with consistent font-size-sm and color: var(--color-text-muted). Define it once in app.css rather than in each page's scoped styles.
