Custom per-tier — Design A vs Design B

Two sub-designs of the Custom per-tier mode. Same end-state, two different inputs. A: type one cap per tier. B: type one base cap; the system multiplies it across tiers using each tier's multiplier.

APer-tier inputs — one input per tier. Empty = rule's max applies as hard cap. Filled = that tier's hard ceiling. Maximum control, more typing.

What the merchant does: types one ₹ value. The per-tier ceilings are auto-computed. Best when the merchant thinks of the cap as "scaled by tier" — keeps the ladder proportional to multipliers and removes the chance of inconsistent per-tier numbers. Trade-off: the merchant can't break the symmetry — e.g., they can't cap Bronze tight while leaving Diamond loose without going back to Design A.
