E2Mode switch warning — leaving Custom with data

⚠ Switch to Hard cap?

You have 2 per-tier overrides and a base cap of ₹500 configured in Custom per-tier mode. Switching to Hard cap will not delete them — they'll be preserved and re-applied if you switch back.

Until you switch back: rule caps apply as hard ceilings for every tier. Diamond customers no longer earn ₹2,000 — they earn ₹450 (the rule's max).

Switching modes is non-destructive. We preserve Custom data when switching away so the merchant can return; we just stop applying it. The modal explicitly tells them what their customers will earn after the switch.

5Runtime cap resolution — what the earn flow does per mode

Per earn-event, after base reward and multipliers compute:

let gross = rule.base_reward(order) // 5% × ₹20,000 = ₹1,000 let mult = max(loyalty_mult, membership_mult) × campaign_mult let raw = gross × mult // ₹1,000 × 5 = ₹5,000 let cap = match program.cap_mode { "hard" => rule.max_amount, // ₹450 "soft" => rule.max_amount × mult, // ₹450 × 5 = ₹2,250 "custom" => tier.max_amount_override // override wins .or(program.custom_base_cap × tier.multiplier) // base × mult .or(rule.max_amount), // fall back to rule } let result = min(raw, cap)

Resolution table

Modebaseoverriderule.max_amountEffective cap
Hard——₹450₹450
Soft——₹450₹450 × tier_mult
Custom——₹450₹450 (fall back)
Custom₹500—₹450₹500 × tier_mult
Custom—₹750 (Gold)₹450₹750 (override wins)
Custom₹500₹900 (Gold)₹450₹900 (override wins)
Custom₹500——₹500 × tier_mult (no rule cap to fall back to)
Custom resolution order (highest precedence first): per-tier override → program base × tier multiplier → rule's own cap → uncapped. This means even an "empty" Custom mode still produces a sane ceiling whenever the rule itself has a cap.
6Schema additions — migrations
ALTER TABLE loyalty_programs
  ADD COLUMN cap_mode TEXT NOT NULL DEFAULT 'hard',     -- 'hard' | 'soft' | 'custom'
  ADD COLUMN custom_base_cap DOUBLE PRECISION;          -- nullable; only meaningful when cap_mode='custom'

ALTER TABLE loyalty_tiers
  ADD COLUMN max_amount_override DOUBLE PRECISION;      -- nullable; per-tier override

ALTER TABLE loyalty_programs
  ADD CONSTRAINT cap_mode_check CHECK (cap_mode IN ('hard','soft','custom'));

Existing merchants get cap_mode = 'hard' by default (the recommended, conservative behavior). The previous bug-behavior is cap_mode = 'soft' and only activates when a merchant explicitly chooses it.
