New input column. Each row gets an editable ₹ input. The styling distinguishes customised tiers (purple border, bold value, "Custom" badge, ↻ reset link) from default tiers (grey italic, "Default" badge, no reset). The helper bar tells the merchant at a glance how many tiers they've tuned, and gives two power moves: Reset all (back to rule's max) and Fill from formula (auto-populate as cap × multiplier — same numbers Soft cap would produce, but materialised so the merchant can then tune individual tiers).

Behavior & edge cases

  • Falling back when a tier has no custom cap: the cap input shows the rule's max in italic+grey (the "Default" state). At runtime, the customer earns under the rule's max_amount.
  • Customer with no tier yet: uses the rule's max_amount (same as a Bronze with default cap).
  • Switching back to Hard or Soft from Custom: the per-tier values are preserved but not applied — a small note appears under the inactive Custom pill: "your per-tier values are saved; re-enable to use them". This protects merchants from losing tuning they spent time on.
  • "Fill from formula" power move: populates every tier as rule_cap × tier_multiplier (so Diamond = ₹450 × 5 = ₹2,250). Useful starting point for merchants who want generous-but-still-capped top tiers.
  • Validation: per-tier cap must be ≥ 0. We allow 0 (effectively no reward for that tier) and warn if < the multiplier × the rule's typical small-order earn. Empty = inherit rule default.
  • Compatibility with Soft cap mode: Soft cap and Custom cap are mutually exclusive. Hard cap is the default that all merchants start at.
