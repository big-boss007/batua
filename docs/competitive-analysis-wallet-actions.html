Wallet Operations: Competitive Analysis

How do loyalty/store-credit platforms handle credit issuance, debits, and expiry? Feature-by-feature comparison across 13 competitors to inform Batua's wallet action design.

Prepared for: Batua (Breeze Retention Suite) Date: 31 March 2026 Platforms analysed: 13

Executive Summary

We surveyed 13 loyalty, store-credit, and wallet platforms across Shopify-native, SMB apps, and enterprise solutions. The goal: understand how competitors let merchant admins issue credits, debit/remove balances, and force-expire points or cash from individual customer wallets.

The findings revealed that issue and debit are table-stakes features offered by every platform, while force-expire was a significant industry gap. Batua has now shipped all three operations — Add, Remove, and Expire — for both cash and points, with a unified tab-based modal, per-bucket targeting, and graded confirmation. Batua is the first Shopify-ecosystem app to offer per-customer force expiry.

Platform Deep Dives

S
Shopify Native Store Credit
Built-in (July 2024) -- No app needed
Platform Native Credit + Debit

Issue Flow

Customers > Select customer > Store credit panel > Edit > Credit adjustment type > Enter amount > Optional expiry date > Toggle "Notify customer" > Save

Debit Flow

Same path but select Debit adjustment type. Fails if amount exceeds balance. GraphQL: storeCreditAccountDebit mutation.

Fields Available

  • Amount (required, max $15,000/customer)
  • Currency (dropdown if multi-currency)
  • Expiry date (optional, specific date)
  • Customer notification toggle
  • No reason/note field -- notable gap

Key Limitations

  • Requires "New Customer Accounts" (email OTP login)
  • No reason/comment field for audit
  • No points system (cash only)
  • Staff need dedicated permission grants
  • Uses FEFO (first-expiring, first-out) for redemption
Batua Opportunity: Shopify's lack of a "reason" field is a glaring omission for merchant support teams. By including reason categories + free-text notes, Batua provides better auditability out of the box.
R
Rise.ai
Store Credit & Gift Card Specialist
Best-in-class Credit UI

Issue Flow (Best in Class)

  • Dedicated "Issue Store Credit" button in header, wallet list, and customer detail
  • Customer email (auto-creates wallet if new)
  • Amount + reason dropdown + internal note
  • Expiry: "Never" / dynamic (30d, 60d) / fixed date
  • Email notification toggle
  • Tagged as "Manually Issued" in records

Debit Mechanisms

  • "Adjust Balance" -- silent, no customer notification
  • "Change Balance" on gift cards -- set to any value
  • Negative values in bulk CSV imports
  • "Disable Gift Card" for full deactivation

Bulk Operations

  • CSV upload: email, first name, last name, amount, tag, reason, "Expires on" column
  • Automated workflows for trigger-based issuance
  • Refund-to-store-credit flows

Unique Differentiators

  • Multi-channel entry points for issuance
  • Flexible expiry at individual credit level
  • Internal note vs customer-facing reason separation
  • Gift card lifecycle management
Batua Takeaway: Rise.ai's "reason dropdown + internal note" separation is excellent UX. The reason category (Refund, Goodwill, etc.) enables reporting, while the free-text note serves the support team. Adopt this pattern.
S
Smile.io
SMB Loyalty Points
Add/Remove Points No Force Expire

Adjustment Flow

Single "Adjust balance" button on customer profile Points card. Positive number to add, negative to remove. No email notification sent. Visible in customer Activity card history.

Redemption Reversal

Separate "Refund points" action on specific redemption entries. Two paths: Customer Profile > Activity card, or Program > Activity. Refunds points and removes unused coupon.

Expiry (Global Only)

  • Inactivity-based: 3 days to 2 years
  • Warning + last-chance email thresholds
  • Growth, Plus, Enterprise plans only
  • Disabling does NOT restore expired points

Key Design Pattern

Single numeric field for both add and debit (sign determines direction) is the simplest possible UI. However, it increases error risk -- no confirmation step, easy to accidentally add instead of remove.

Y
Yotpo Loyalty
SMB Loyalty Points (formerly Swell)
Adjust Balance VIP Impact Warning

Adjustment Flow

"Adjust Points Balance" button > popup with amount + reason/history entry + visibility toggle (customer-facing vs internal). Positive to add, negative to deduct.

Critical Caveat

Manual adjustments affect lifetime point balance, which impacts VIP tier status. Docs explicitly warn about "unintended consequences" and suggest alternative methods for some scenarios.

Expiry Options

  • Date-Based: points expire X months after earning
  • Activity-Based: expire after inactivity period
  • Global setting only, Premium+ plans
  • Changing retroactively resets countdown for all

Reason Visibility Control

Toggle whether the adjustment reason appears in the customer's point history or stays internal. This is a thoughtful feature that balances transparency with operational discretion.

Batua Takeaway: Yotpo's warning about tier impact is important. When Batua debits points, the UI should show tier implications (e.g., "This debit will drop the customer from Gold to Silver"). Also adopt the reason visibility toggle.
L
LoyaltyLion
Mid-Market Loyalty
Give / Remove Per-Entry Undo

Issue Flow

Actions dropdown > "Give points" > Amount + reason (customer-visible). Points immediately approved and claimable.

Debit Flow

Actions dropdown > "Remove points" > Amount + reason. Additionally, each manual entry has a "Remove" undo button. Bulk removal only via emailing support.

4 Expiry Methods (Most Flexible)

  • Last Purchase: full balance expires if no purchase within period
  • Last Balance Change: resets on any earn/spend/manual action
  • Date Earned (2025): individual batches expire separately
  • Calendar Date (2025): annual purge of old points

Notable Pattern

Separate "Give" and "Remove" actions (not a single +/- field) reduces accidental errors. The per-entry undo button is a valuable safety net.

Batua Takeaway: LoyaltyLion's separate "Give" vs "Remove" verbs (instead of +/- on one field) is safer UX. Their per-entry "Remove" undo button is also worth considering for the transaction history.

Talon.One
Enterprise Promotion Engine
Full CRUD Subledgers SOC 2 Audit

Issue Flow

Customer > Loyalty Points tab > Select program & subledger > "Add Points" > Amount + reason + activation timing (default vs immediate).

Debit Flow

"Deduct Points" in same tab. Supports negative balances if program-configured. Active point deduction controls for rollback scenarios.

Unique: Subledgers

Multiple wallets within one loyalty program. Points earned in Store A are tracked separately and can only be redeemed at Store A. Powerful for multi-brand merchants.

Enterprise Features

  • Customer Support RBAC role
  • Loyalty card management (import, block, transfer)
  • CSV import with per-entry expiry dates
  • Rule Builder for automated logic
  • Full audit logs (SOC 2, ISO, GDPR)

Gap Analysis & Opportunities for Batua

✅ Implemented — Industry First

Per-Customer Force Expire

Only 2 of 13 competitors offer this (Antavo at enterprise tier, Open Loyalty as open-source). Batua is the first Shopify-ecosystem app to let admins force-expire a specific customer's balance per bucket — with multi-bucket selection, irreversibility warning, and type-to-confirm ("EXPIRE") safety.

✅ Implemented — Differentiator

Unified Cash + Points Operations

Most platforms are either cash-only (Rise.ai, Shopify) or points-only (Smile.io, Yotpo, LoyaltyLion). Batua now ships a unified Wallet Action modal with tab-based Add/Remove/Expire that handles both cash and points units — the only platform in the Shopify ecosystem to do so.

✅ Implemented

Issue Credit with Reason + Notes

Batua's Add tab includes: per-bucket targeting, amount with validation, optional expiry days, reason category pills (Refund, Goodwill, Apology, Compensation, Promotional, Other), free-text reason, internal reference field, and customer notification toggle. Matches Rise.ai's best-in-class pattern.

✅ Implemented

Debit with Reason + Confirmation

Batua's Remove tab uses explicit verb separation (not +/- numeric). Per-bucket debit with live balance display, max-amount validation, reason pills + free text, and type-to-confirm (echo the exact amount). Follows LoyaltyLion's separate-verb best practice.

Future Differentiator

Tier Impact Preview

Yotpo warns that point adjustments affect VIP tiers but doesn't show the impact. Batua can preview: "Debiting 500 points will move this customer from Gold (2x) to Silver (1.5x)." No competitor does this. Not yet implemented — candidate for next iteration.

✅ Implemented — Differentiator

Per-Bucket Targeting

Batua's wallet action modal targets specific buckets for all three operations. Add: choose Courtesy Points vs Reward Points (points) or Store Credit vs Customer Funded (cash). Remove: select from buckets with balance. Expire: multi-select checkboxes across all buckets. No SMB competitor offers this granularity.

Future Enhancement

Reason Visibility Control

Only Yotpo offers a toggle for whether the reason is customer-visible or internal-only. Batua currently has reason category + free-text reason + internal reference (Rise.ai pattern), but no visibility toggle for customer-facing vs internal. Candidate for next iteration.

✅ Implemented

Transaction-Level Audit Trail

Batua's wallet action success state surfaces the transaction ID, amount affected, and new balance. Full ledger history visible on the customer detail view. Matches enterprise-grade audit expectations.

Recommendations for Batua's Wallet Action Modal

✓

Use Separate Action Verbs, Not +/- Numeric — SHIPPED

Implemented as colour-coded Add (green) / Remove (red) / Expire (amber) tabs in the Wallet Action modal. Each tab has distinct field sets, visual treatment, and confirmation flows. Follows LoyaltyLion's separate-verb best practice.

✓

Adopt Rise.ai's Reason Architecture — SHIPPED

Implemented with three-part reason: category pills (Refund, Goodwill, Apology, Compensation, Promotional, Other — contextual per action) + free-text reason + internal reference field (e.g., Shopify #1234, support ticket #567). Matches the most complete pattern across all competitors.

✓

Build Per-Customer Force Expire (Industry First) — SHIPPED

Implemented as Expire tab with multi-bucket checkbox selection, per-bucket balance preview, irreversibility warning banner, and type "EXPIRE" to confirm. Batua is the first Shopify-ecosystem app to offer per-customer, per-bucket force expiry.

4

Show Tier Impact for Point Debits — NEXT

When debiting points, preview whether the customer's effective tier will change. E.g., "New qualifying value: ₹4,500 (was ₹5,000). Customer will drop from Gold to Silver at next evaluation." No competitor does this proactively. Candidate for next iteration.

✓

Implement the Tab-Based Unified Modal (Novel but Justified) — SHIPPED

Shipped as a unified Wallet Action modal with Add/Remove/Expire tabs. Pre-selects unit (cash/points) from the entry point. Colour-coded tabs with adaptive field sets. Customer banner with current balance. Balance preview with projected new balance. The first platform to ship this pattern.

✓

Escalate Confirmation for Destructive Actions — SHIPPED

Implemented with graded confirmation: Add → single confirm. Remove → type the exact amount to confirm. Expire → type "EXPIRE" to confirm + irreversibility warning. All confirmation steps show the resulting new balance and a detailed summary (customer, bucket, amount, reason).
