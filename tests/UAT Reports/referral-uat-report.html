Stakeholder 1: Merchant Admin

Admin panel at /admin/referrals — 4 tabs: Program, Codes, Analytics, Conversions

#1 Program Tab — View/Edit Referral Program Settings

BUG
  1. Navigate to /admin/referrals
  2. Program tab is selected by default
  3. Observe form fields: Referrer Reward, Referee Reward, Max Referrals, Program Active toggle
Bug: All form fields display 0 on page load instead of the actual database values. The API (GET /referrals/programs/{merchant_id}) returns correct data (referrer: 60, referee: 32, max_referrals: 16), but the frontend form is not populated with the response. This was confirmed across multiple page reloads.

#2 Program Tab — Update Program Settings

FAIL
  1. Fill Referrer Reward = 60, Referee Reward = 32
  2. Click "Update Program" button
  3. Check API response
Failure: The POST /referrals/programs API returns 422 Unprocessable Entity. Response: "missing field `merchant_id` at line 1 column 104". The frontend sends the request body without the required merchant_id field. No error feedback is shown to the user — the form appears to succeed silently.

#3 Codes Tab — View List of Referral Codes

  1. Click "Codes" tab
  2. Observe "All Codes" table below the create form
  3. Verify codes match database records
Result: All 4 codes (RAJESH2, VIKRAM1, KIRAN4, POOJA3) displayed correctly with Customer ID, Conversions count, and Active status badge. Table columns: CODE, CUSTOMER ID, VANITY, CREATOR, CONVERSIONS, STATUS.

#4 Codes Tab — Create Auto-Generated Code

FAIL
  1. Enter Customer ID c0000000-0000-0000-0000-000000000019 (Sunita Mishra)
  2. Leave Vanity and Creator toggles off
  3. Click "Create Code" button
  4. Check if new code appears in list
Failure: The POST /referrals/codes API returns 422 Unprocessable Entity. Response: "missing field `merchant_id` at line 1 column 126". The new code is not created in the database.

#7 Analytics Tab — View Referral Analytics

BUG
  1. Click "Analytics" tab
  2. Observe analytics cards: Total Codes, Total Referrals, Conversions, Conversion Rate
  3. Verify conversion rate calculation
Bug: The conversion rate displays as 0.3% but should be 28.6%. The API returns conversion_rate: 0.2857 (a decimal fraction). The UI appears to format this as (0.2857).toFixed(1) + "%" = "0.3%" instead of correctly computing (0.2857 * 100).toFixed(1) + "%" = "28.6%". The other metrics (4 Total Codes, 14 Total Referrals, 4 Conversions) display correctly.

#8 Conversions Tab — View Conversion List with Fraud Signals

PASS
  1. Click "Conversions" tab
  2. Observe conversion table: Referrer, Referee, Order, Fraud Signals, Date
Result: Conversions table displays correctly with 1 conversion record. Columns: Referrer (truncated UUID), Referee (truncated UUID), Order (order:ref-3), Fraud Signals (green "clean" badge), Date (21 Mar 2026, 01:47 am). The date formatting and fraud signal badge rendering are correct.

#9 Program Tab — Data Not Populated on Load (Confirmed)

BUG
  1. Navigate to /admin/referrals (fresh page load)
  2. Verify API call succeeds with GET /referrals/programs/{id} returning 200
  3. Check form field values
Bug (confirmed): Reproduced consistently across multiple reloads. The API returns: referrer_reward_amount: 60, referee_reward_amount: 32, max_referrals_per_customer: 16, is_active: true. The form shows: 0, 0, 0, true. The form state is initialized with defaults (0) and never updated from the API response. Only the is_active toggle reflects the correct state.

#10 Analytics Tab — Suspicious Count Missing from UI

BUG
  1. Click "Analytics" tab
  2. Check for "Suspicious" or "Flagged" metric card
  3. Verify API response includes total_suspicious
Bug: The API response includes total_suspicious: 0 but this metric is not displayed in the analytics UI. Only 4 cards are shown (Total Codes, Total Referrals, Conversions, Conversion Rate). A "Suspicious" or "Flagged" count card should be added for fraud monitoring.
